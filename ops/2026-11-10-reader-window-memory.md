# 2026-11-10 大文件阅读和反色导出时页面崩溃：内存随页数增长

## 线上现象

11-09 中午上线中断追踪后，到 11-10 上午共有 5 次 `pdf_interrupted`（同期 204 次 pdf_start）。5 次都是大文件（3 次 10–50MB、2 次 50MB 以上），页数在 228 到 2538 之间，中断时已处理到很后面（第 102、260、376、2282、2364 页）。5 次都在前台（background=0），其中 4 次 hidden_ms=0。分布：reader 3 次（iOS 2 次是同一用户、同一个 2538 页文件重试，Android Chrome 1 次），invert 2 次（Windows Edge 桌面和笔记本各 1 次）。判断是标签页内存超限被杀，不是后台回收。

## 原因

1. 两个工具都不调用 PDF.js 的 `page.cleanup()`。按显示用途渲染后，PDF.js 不会自动清理，每页的 operator list 和解码后的图片（`page.objs`）会一直留在主线程，直到文档销毁。页数越多、图片越大，内存越高。已在 pdfjs-dist 5.6.205 源码中确认：只有打印用途渲染完才会自动清理。
2. reader 给每一页都保留原图 JPEG 和调暗后的 JPEG，还保留切换主题时的各个变体，并给每页都放一个 `<img>`。11-04 的修复只释放了 canvas，Blob 仍然随页数增长。11-09 的反色导出修复已说明「阅读器的缓存是另一条路径，这次没有改」。

## 改动

- `components/downloader.tsx`：每页渲染完调用 `page.cleanup()`。组装阶段需要页面时会重新 `getPage`，不受影响。
- `components/pdf-viewer.tsx`：
  - 首轮只读取每页尺寸（`getPage` + 视口，不渲染）。完整渲染第 1 页后进入阅读状态，每 50 页发布一次占位。全部页的尺寸读完后记 `pdf_success`。
  - 只渲染当前页前后 5 页，超出 8 页的页面释放图片、撤销 object URL，回来时重新渲染。未渲染的页用相同宽高比的占位块，跳页和滚动位置不变。
  - 切换主题、图片模式或滑块后，只重新处理窗口内的页面，其他页滚到附近时再按当前设置渲染。每页最多缓存 3 个变体。
  - 渲染辅助函数里也调用 `page.cleanup()`。文件替换或卸载时先取消所有渲染循环，再 `destroy()` 文档；原来文档没有销毁。
  - `objectUrl` 的映射表原先会一直引用所有 Blob，现在释放页面时同时删除对应项。

## 统计口径变化

reader 的 `pdf_success` 原来要等所有页渲染完，现在是所有页的尺寸读完、第 1 页显示后。成功更快，读到一半就离开的 `pdf_abandon` 会明显减少。与 11-10 之前的数据比较 reader 成功率时要注意这一点。窗口内后续页面渲染失败仍按原来的方式记为 `pdf_error`（stage=preview）。

## 验证

- 300 项 Node 测试、TypeScript、生产 build 通过。ESLint 在 `pdf-viewer.tsx` 报 2 处 set-state-in-effect，是原有写法（原来是 3 处）；`downloader.tsx` 无问题。
- 本地生产构建对比，旧版为 HEAD `562c439`。Playwright 自带的 Chromium 无头模式，拦截所有非 localhost 请求，不往线上发数据。内存是浏览器全部进程 RSS 之和：

| 场景 | 旧版 | 新版 |
|---|---|---|
| 阅读 1500 页文字 PDF（3.6MB），读完所有页 | 120 秒，峰值 1376MB，1500 个 `<img>` | 4 秒，547–620MB，6–14 个 `<img>` |
| 阅读 300 页扫描式 PDF（157MB，每页一张全页 JPEG） | 47 秒，峰值 2804MB | 19 秒，600–780MB |
| 反色导出 1500 页文字 PDF | 28 秒，峰值 703MB | 28 秒，峰值 631MB |
| 反色导出 300 页扫描式 PDF | 64 秒，峰值 2473MB | 47 秒，峰值 1359MB |

- 新版阅读器连跳 36 次（夹带连续滚动），`<img>` 始终 14 个；内存在 600–1100MB 之间波动，强制 GC 后回到 600–800MB，没有持续增长。主线程 JS 堆约 13MB。
- 跳到远处的页面后，目标页正常显示，第 1 页的图片已释放。切换主题后，窗口内的页面都完成重新调暗。393×852 手机视口跳到第 1234 页，0.8 秒内出图，版面正常。
- 反色导出的新旧产物只有 ModDate 不同，其余字节一致。
- 生命周期：本地 1500 页阅读只产生 `pdf_start` 和 `pdf_success`，结束后 sessionStorage 中没有残留操作记录。
- 没有在真实 iOS 或 Android 设备上验证。

无 URL、目标词或页面定位变化，不更新 PAGES.md。
